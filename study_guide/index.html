What is this app?

KitchenStock Pro is a smart kitchen operations app. It helps small kitchens manage ingredient stock, record wasted items, track production batches, and view simple insights.

What problem does it solve?

Many kitchens lose money because they do not clearly track stock, waste, or production usage. This app gives them one place to control inventory and reduce avoidable loss.

Main Features

Authentication

Users can register, sign in, sign out, and reset passwords.

Onboarding

First-time users see an intro flow explaining the app value.

Dashboard

Shows stock counts, waste records, batch counts, and low-stock items.

Inventory

Add, edit, delete, search, and review ingredient stock levels.

Waste Tracking

Record wasted ingredients, reasons, reporter name, and date.

Batch Tracking

Record a batch and automatically deduct ingredient usage from stock.

Reports

Review waste and usage summaries with ranked insight blocks.

Profile

Shows signed-in user details and highlights app capability.

Settings

Stores simple preferences and can replay onboarding for demos.

Technologies Used

Flutter

Builds the user interface. Every screen, button, form, and card comes from Flutter widgets.

Dart

The programming language used to write the app logic and widget code.

Firebase Authentication

Handles user sign up, sign in, logout, and password reset.

Cloud Firestore

Stores the app data online, such as inventory, waste, and batches.

Shared Preferences

Stores simple local settings like onboarding completion and app preferences.

Material 3

Provides the design system and modern Flutter UI components.

Example 1: Login

User enters email and password, the app calls Firebase Auth, and then the auth state decides which screen to show.

Example 2: Add inventory item

User submits the form, Firestore stores the item, and the inventory list refreshes from the stream.

Firestore Collections

inventory

Stores ingredient name, quantity, and unit.

{
  "name": "Flour",
  "quantity": 20,
  "unit": "kg"
}

waste

Stores wasted item info and reason.

{
  "itemName": "Flour",
  "wastedQty": 2,
  "unit": "kg",
  "reason": "Spoiled"
}

batches

Stores batch details and used ingredients.

{
  "batchName": "Cake Mix",
  "ingredients": [
    { "name": "Flour", "used": 5, "unit": "kg" }
  ]
}

Why there is a services folder

Services keep logic out of the UI. For example, the auth service handles sign in and sign up instead of making every screen talk directly to Firebase in a messy way.

Why there is a widgets folder

Widgets like the bottom navigation and section cards are reused in many places, so putting them in one folder avoids repetition.

How to Explain It in a Presentation

  1. Start with the problem: kitchens lose money when inventory and waste are not tracked well.
  2. Explain the solution: this app manages stock, waste, batches, and insights in one system.
  3. Mention the tech stack: Flutter for UI, Firebase Auth for login, Firestore for data.
  4. Show the user flow: onboarding, register/login, dashboard, inventory, waste, batch, reports.
  5. End with impact: better inventory control, lower waste, smarter kitchen decisions.

Study Tips for a Clueless Student

Memorize these 4 ideas

  • Flutter builds the screens.
  • Firebase Auth handles users.
  • Firestore stores app data.
  • Services help keep code cleaner.

If asked “why this project?”

Say it solves a real operations problem for small kitchens by helping them reduce waste and manage stock more efficiently.

If asked “why Flutter?”

Say Flutter allows fast cross-platform development from one codebase while still giving a modern mobile UI.

If asked “why Firebase?”

Say Firebase gives authentication and cloud data storage without building a full custom backend.
