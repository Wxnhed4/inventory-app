# Technology Stack

This file explains the main technologies, tools, and packages used in the project.

## Core Technologies

### Flutter

`Flutter` is the main framework used to build the app UI. It allows the project to run from a single codebase across Android, iOS, web, desktop, and more.

In this project, Flutter is used for:

- screen layouts
- forms
- navigation
- stateful widgets
- theming
- Material 3 components

### Dart

`Dart` is the programming language used by Flutter. All app logic, screen code, services, and models are written in Dart.

It is used here for:

- business logic
- asynchronous Firebase calls
- widget composition
- date formatting integration

## Backend and Cloud Services

### Firebase Core

Package:

- `firebase_core`

Purpose:

- connects the Flutter app to Firebase
- initializes the Firebase project before the app starts

### Firebase Authentication

Package:

- `firebase_auth`

Purpose:

- handles user registration
- handles login and logout
- supports password reset
- provides the auth state stream used by the app shell

Used in:

- onboarding/auth app flow
- login screen
- register screen
- forgot password screen
- profile screen

### Cloud Firestore

Package:

- `cloud_firestore`

Purpose:

- stores the app data in the cloud
- keeps inventory, waste, and batch records
- supports live updates through streams

Collections currently used:

- `inventory`
- `waste`
- `batches`

## Utility Packages

### Intl

Package:

- `intl`

Purpose:

- formats dates in screens such as waste, batch, and reports

### Shared Preferences

Package:

- `shared_preferences`

Purpose:

- stores small local settings on the device
- remembers onboarding completion
- stores app settings such as alerts and compact mode

## FlutterFire Configuration

### FlutterFire generated configuration

File:

- `lib/firebase_options.dart`

Purpose:

- stores the Firebase configuration generated by FlutterFire CLI
- allows Firebase initialization for the correct platform

## Development Tools

### Flutter SDK

Used to:

- build the app
- run the app on emulator/device
- analyze code
- run widget tests

Common commands:

```bash
flutter pub get
flutter run
flutter analyze
flutter test
```

### Flutter Lints

Package:

- `flutter_lints`

Purpose:

- applies recommended coding rules and quality checks

### Flutter Test

Package:

- `flutter_test`

Purpose:

- used for widget testing
- currently used to validate the onboarding screen test

## Project Architecture Tools

### Theme system

Files:

- `lib/core/theme/app_colors.dart`
- `lib/core/theme/app_theme.dart`

Purpose:

- centralizes colors
- centralizes visual styling
- keeps the app UI consistent

### Service layer

Files:

- `lib/services/auth_service.dart`
- `lib/services/app_preferences_service.dart`

Purpose:

- moves common logic out of screens
- keeps the UI cleaner
- makes the project easier to maintain and explain

### Shared UI widgets

File:

- `lib/widgets/section_card.dart`

Purpose:

- provides reusable UI blocks such as section cards, headings, metric tiles, and empty states

## Summary

The project is built with:

- `Flutter` for cross-platform UI
- `Dart` for application logic
- `Firebase Auth` for authentication
- `Cloud Firestore` for cloud database storage
- `Shared Preferences` for lightweight local settings
- `Intl` for date formatting

Together, these tools make the app suitable for a final project because they show:

- mobile UI development
- cloud integration
- authentication
- CRUD operations
- persistent local settings
- clean structuring with reusable components
